# splayed 0.1.0-pre-alpha.1

**This is a pre-alpha.** It exists so more people can test it. Please read this page before using it
with real coins.

splayed is a keyless tool for separating the **BTC**, **XBT** (Bitcoin BLAKE2b) and **ECX** (eCash)
copies of the same coins after the 2026 forks. It builds replay-protected PSBTs, your wallet signs
them, and splayed verifies and broadcasts each split only to its own chain, over Tor. Start with the
[Web UI guide](../user/web-ui-guide.md).

## Status

- **Not independently security-reviewed.** The author has reviewed the whole branch (the web UI
  server, token and host handling, the broadcast, track and fee-bump logic, QR parsing), and two
  real bugs came out of it, now fixed. No one else has audited the signing checks, planner, network
  layer or web UI.
- **Proven on mainnet once.** One real coin has been split end to end (ECX and XBT away from BTC,
  BTC confirmed untouched), signed with a SeedSigner. It has also been exercised extensively against
  real Bitcoin Core, Knots and eCash nodes on regtest (`deno task test:integration`), and with
  Sparrow and Shrike on the regtest playground. Backends have not been tested against every real
  server type, and real bugs were found and fixed this way (see `CHANGELOG.md`).
- **Use one small coin first.** Do the whole route (plan, sign, verify, broadcast, track, rescan) on
  one small coin before anything larger, and keep your BTC copies untouched until both fork splits
  are deeply confirmed.
- ECX uses `explorer.ecash.com` over a Tor exit by default, with `esplora.ecash.ninja` available as
  a fallback (it needs your explicit confirmation).

## What is in this release

- **Binaries** for Linux x86_64 and aarch64, macOS arm64 and x86_64 and Windows x86_64, each with
  its pinned Tor (Tor Browser 16.0, tor 0.4.9.15) except Linux aarch64, which needs a `tor` on
  `PATH`. Only the Linux x86_64 build has been run from a clean extract; the macOS and Windows
  builds are cross-compiled and have not been run on those systems yet.
- **StartOS packages** (`.s9pk`) for x86_64 and aarch64. The x86_64 package has run on a StartOS
  0.4.1 server (Web UI, token, node, Tor scan, backup and restore); the aarch64 one has not been
  installed.
- **Docker:** build it from the source with `docker compose` (see the README); the image builds for
  amd64 and arm64, and the arm64 image has only been started under emulation.
- Verify before running: `sha256sum -c --ignore-missing SHA256SUMS` (it lists every file), and
  `gpg --verify SHA256SUMS.asc SHA256SUMS` against the key in [SECURITY.md](../../SECURITY.md).

## Known limitations

- Inputs with script timelocks (CLTV, CSV) and miniscript are unsupported and refused on import: a
  timelock can't be combined with the ECX replay marker.
- Taproot script trees and `combo()` descriptors are unsupported (Taproot key path works).
- PSBT v2 (BIP370) input is unsupported.
- Fee bumps are not available for BTC transactions or fan-out transactions, and CPFP is not
  available for donor or multi-output transactions.
- XBT splits need a signer that makes `SIGHASH_ALL|SIGHASH_UNIFIED` (0x21) signatures. Stock
  hardware wallets can't; the advanced donor route is the workaround and has not been tried with a
  real hardware wallet.
- Animated-QR signing (UR `crypto-psbt`): export and **Scan signed** (camera import) have both
  worked with a SeedSigner; still untried with a Jade, Keystone or Passport.
- BBQr and plain base64 QR codes are not supported.
- Managed Tor has only been run on Linux x86_64; the macOS and Windows bundles are hash-checked but
  not run.

## Please report back

Use the **Tester report** issue template, and say what worked as well as what didn't. Redact
descriptors, xpubs, addresses and txids for wallets you use with real coins. Vulnerabilities go to
the contact in [SECURITY.md](../../SECURITY.md), not a public issue.
