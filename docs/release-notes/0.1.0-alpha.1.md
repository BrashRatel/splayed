# splayed 0.1.0-alpha.1

**This is the first alpha.** It is still **not security-reviewed**, and it moves real coins: start
with one small coin. The [0.1.0-pre-alpha.1 notes](0.1.0-pre-alpha.1.md) explain the status, the
"use one small coin first" advice and the known limitations, which all still apply. This page lists
what changed since [0.1.0-pre-alpha.2](0.1.0-pre-alpha.2.md). The full list is in the
[CHANGELOG](../../CHANGELOG.md).

## What changed

- **Fee bumps (RBF) for BTC and fan-out transactions.** `bump` (and **Fee bump…** in the web UI) now
  replaces the BTC transactions of the BTC-first route and donor fan-outs. A bumped BTC transaction
  no longer holds back the XBT split that waits for it. CPFP for these transactions is not available
  yet.
- **`--batch linked`** combines only coins that are already linked on chain (same address, or
  created by your own transactions that spent from a common address), to save fees without linking
  anything new. It is also in the web UI's plan forms.
- **Coins that can only exist on one chain are recognized.** `scan` checks whether a single-chain
  coin's creating transaction could be valid anywhere else (an XBT `0x21` signature, the ECX replay
  marker, a post-fork coinbase, one of splayed's own splits), and shows proven coins as "XBT only"
  (or BTC, ECX) with the reason. This has not been tried against real chains yet.
- **The web UI's Coins tab shows where each coin's split is**, one badge per chain, from planned to
  confirmed.
- **Donor routes in the web UI are opt-in.** The Donors tab first explains what a donor reveals on
  chain. Until you turn donor routes on, the UI runs no donor command. The command line is
  unchanged.
- **splayed says what kind of wallet each descriptor is** (for example "Multisig 2-of-3 · native
  (wsh) · sorted keys"), in the web UI and in `import`, `descriptors`, `scan` and `status`.
- **RPC passwords on StartOS.** The StartOS package has a **Server passwords** action for nodes you
  add in the web UI with an RPC user. The web UI now says where to set a node's password variable.
- **Fixed: `Start splayed.cmd` on Windows opened File Explorer instead of the browser.**

## What has and has not been run

- The Windows browser fix was run on Windows, and the StartOS **Server passwords** action on a
  StartOS server, both from test builds of this branch.
- The Linux x86_64 and Windows x86_64 archives have been run from a clean extract. The macOS
  archives and the Linux aarch64 archive are built and hash-checked but **have not been run on real
  machines**.
- The x86_64 StartOS package for this release was installed on a StartOS server as an update over
  the previous version. The aarch64 one has not been installed.
- The chain-specific proofs and `--batch linked` have only been run on test chains, not mainnet.
- The signer, hardware-wallet and backend gaps listed in [TODO.md](../../TODO.md) are unchanged.

Verify before running: `sha256sum -c --ignore-missing SHA256SUMS`, and
`gpg --verify SHA256SUMS.asc SHA256SUMS` against the key in [SECURITY.md](../../SECURITY.md). Report
back with the **Tester report** issue template; vulnerabilities go to the contact in SECURITY.md,
not a public issue.
