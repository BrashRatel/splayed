# splayed 0.1.0-pre-alpha.2

**This is a pre-alpha.** It exists so more people can test it. Please read the
[0.1.0-pre-alpha.1 notes](0.1.0-pre-alpha.1.md) first: the status, the "use one small coin first"
advice and the known limitations there all still apply. This page lists what changed.

## What changed

- **Node RPC backends speak JSON-RPC 2.0.** A node that implements only 2.0 (bitcoinpr) answered
  every 1.0 request with `-32600 Invalid request` and could not be used at all. Bitcoin Core, Knots
  and the eCash node answer 2.0 the same way, and broadcast handling is unchanged.
- **The Linux aarch64 archive bundles Tor** (Tor Browser 16.0, tor 0.4.9.15), like the other
  platforms, so it no longer needs a `tor` on `PATH`.
- **Windows and macOS archives start without a terminal.** Each has its own `README.txt` (first
  start, the SmartScreen and Gatekeeper prompts for unsigned builds, checking the download) and a
  launcher: `Start splayed.cmd` or `Start splayed.command`.
- **Much wider regtest coverage** (no change for users, but more of the route is now tested against
  real Bitcoin Core, Knots and eCash nodes): multisig up to 3-of-5 and 11-of-15 size estimates,
  hardware-wallet-style and node-wallet signers, lost replies, fee bumps and conflicting spends with
  and without `txindex`, and a regression test for P2SH-wrapped transactions whose txid changes on
  signing. Documentation was reviewed for accuracy, with new notes on pruned nodes and reaching a
  node on the Docker host.
- **StartOS packages** (`.s9pk`, x86_64 and aarch64) are rebuilt on this release.

## What has and has not been run

- The Linux x86_64 and Windows x86_64 archives have been run from a clean extract. The macOS
  archives and the Linux aarch64 archive (and its new Tor bundle) are built and hash-checked but
  **have not been run on real machines**.
- The new Windows and macOS launchers and READMEs have not been tried on those systems.
- The x86_64 StartOS package has run on a StartOS server; the aarch64 one has not been installed.
- The signer, hardware-wallet and backend gaps listed in [TODO.md](../../TODO.md) are unchanged.

Verify before running: `sha256sum -c --ignore-missing SHA256SUMS`, and
`gpg --verify SHA256SUMS.asc SHA256SUMS` against the key in [SECURITY.md](../../SECURITY.md). Report
back with the **Tester report** issue template; vulnerabilities go to the contact in SECURITY.md,
not a public issue.
